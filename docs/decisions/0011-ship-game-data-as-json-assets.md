# Ship game catalog data as JSON assets loaded at runtime

## Context and Problem Statement

Each game's catalog was TypeScript (`config.ts`, `items.ts`, `bundles.ts`) imported into the app. The
Stardew items alone are about 140 kB, all of it in the initial `main` bundle, parsed as code before the
first render, and re-downloaded with every code change because it shares the hashed bundle. The editors
had to print Prettier-style TypeScript to export it. More games will make this worse.

## Considered Options

- JSON files in the game app's assets, fetched at runtime and checked against a small schema.
- Keep TypeScript modules, but lazy-load them with dynamic `import()`.
- Keep TypeScript modules imported eagerly (the old way).

## Decision Outcome

Chosen option: "JSON files in the game app's assets", because it takes the data out of the JavaScript
bundles entirely (cached and versioned separately from code), it's a plain data format any tool can read
and write, and the editors can export it directly.

- A game's data is `apps/<game>-cozy-almanacs/src/assets/catalog/<dataset>/config.json`, `items.json` and
  (optionally) `bundles.json`. Edit it with the catalog and bundle editors, which export these files.
- `src/app/catalog/datasets.ts` registers each dataset as a `CatalogDatasetSource` (`id`, `name`, `urls`
  relative to the base href, repo `files`) with `provideCatalogDatasets()`. No data goes in TypeScript.
- Load data only through `CatalogDatasetLoader` (`@cozy-almanacs/state`). It fetches each dataset once
  with `HttpClient`, rejects files that don't match the catalog schema (`catalog-schema.ts`), and
  `loadActive()` fills `CatalogStore` and `BundleStore`. The shell route runs it before the first page.
- When a model in `@cozy-almanacs/models` changes, update `catalog-schema.ts` with it.
- Each game app keeps a spec that checks its shipped JSON against the schema and for broken references
  (`catalogReferenceIssues`).
- Don't add a schema library for this (a runtime dependency needs its own ADR); the check is hand-rolled.

### Consequences

- Good: the Stardew app's initial bundle drops by about 95 kB raw; data and code cache independently.
- Good: the editors export plain JSON, and the files can be validated or generated by any tool.
- Bad: TypeScript no longer checks the data at compile time; the runtime schema check and the app's spec
  stand in for it, and the schema has to be kept in step with the models by hand.
- Bad: the first page waits for one extra request for the data files.

### Confirmation

Code review, `catalog-dataset.loader.spec.ts` and `catalog-schema.spec.ts` in `@cozy-almanacs/state`, and
`apps/stardew-cozy-almanacs/src/app/catalog/datasets.spec.ts`.

## More Information

Refines ADR 0010 (game data lives in its game app), which still decides where the data lives and how the
hub's development build borrows it.
